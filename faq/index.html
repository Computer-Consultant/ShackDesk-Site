Frequently Asked Questions

Common questions about ShackDesk apps, safety, installation, and licensing.

Safety & Trust

Yes. The SmartScreen warning appears because ShackDesk apps are independently developed software that is new to Microsoft's reputation system. It is not an indication of a virus or malware. To proceed, click More info then Run anyway.

ShackDesk is preparing code signing for PortPane, starting with alpha releases. See the PortPane code signing policy for current status. In the meantime, you can verify the integrity of any download by checking the SHA-256 hash posted alongside each release on GitHub. ShackDesk apps are designed to work fully offline. No internet connection is required for any core feature. Apps will never silently connect to any server without your knowledge.

The only optional network activity is anonymous telemetry, which is strictly opt-in and disabled by default. You can review exactly what would be sent before anything leaves your machine using Help → View Collected Data.

No. ShackDesk apps do not collect your callsign, name, email address, IP address, hostname, or any personally identifiable information. Ever.

Optional diagnostics (opt-in only) collect anonymous hardware identifiers to improve compatibility: for PortPane, audio device and COM port names; for RigCheck, the radio model, serial settings, USB cable identifiers, and test results. Each app lets you view every report it has sent. See the Privacy page for full details.

Installation & Compatibility

Requirements vary by app. PortPane requires Windows 10 or Windows 11 (64-bit). Check each app's release page for specific system requirements.

PortPane requires the .NET 8 runtime, which ships with Windows 11. On Windows 10, Windows will prompt you to download it automatically if it is not already present. No third-party software is required.

COM port access is required to display active port assignments and switch between profiles. ShackDesk apps only read port information and switch assignments — they do not modify your radio's configuration or transmit anything over the air.

PortPane

PortPane displays your current audio device and COM port assignments in one place and lets you switch between saved profiles with a single click. It is designed for digital mode operators who regularly switch between modes, software, or radios and need a fast, reliable way to get the right configuration loaded without hunting through Windows settings.

PortPane manages Windows audio device and COM port assignments at the system level — it works alongside any digital mode software. It does not integrate directly with any specific application; it simply ensures the right devices are assigned before you launch your software.

Open Help → View Collected Data. If you have opted into telemetry, you can send a report that includes your device identifiers to help us add it to the recognition database. You can also open a discussion on GitHub Discussions with your device's name and we will look into adding it.

RigCheck Alpha

RigCheck is a CAT communication diagnostic tool. It uses Hamlib — the same rig-control library behind WSJT-X, Fldigi, JS8Call, and Winlink — to test the serial connection to your radio and explain in plain English what is working and what is not. It is for the moment when digital-mode software says it cannot talk to your rig and you do not know why.

Alpha builds are available now from the RigCheck download page. They are for testing and feedback; there is no stable release yet. The connection tests and diagnosis are in place, and automatic radio discovery and environment checks are still being built. New alpha builds are published as the code changes.

Every alpha build stops running 30 days after it was built. This keeps testers on current code, so bug reports are about the latest version, and it steers everyday operators toward stable releases once they exist. The expiry date is in the window title and in Help › About. Once an alpha has expired, starting it shows a notice with a link to the download page — just get the current build. Beta builds will warn but keep running; stable releases never expire.

Usually not. RigCheck finds the rigctl program that comes with WSJT-X or Fldigi, or a standalone Hamlib install, automatically. If you have none of those, install WSJT-X (which most digital-mode operators want anyway) or the standalone Hamlib for Windows, then restart RigCheck.

If RigCheck says Hamlib was not found but you know it is installed, it may be in a location RigCheck does not check yet. Open an issue with the path and it will be added.

Any radio Hamlib supports — several hundred models from Icom, Yaesu, Kenwood, Elecraft, FlexRadio, and others. RigCheck ships quick-start presets for the most common rigs so the right settings are one click away. If yours is missing and you know the settings that work, a preset contribution takes five minutes and helps the next operator with the same radio.

No. The standard tests only read from the radio — frequency, mode, VFO, S-meter, and whether PTT is currently keyed. RigCheck never keys the transmitter. One optional test briefly changes the VFO frequency by 1 kHz to confirm the radio accepts commands, then restores the original frequency; it is off by default and asks for confirmation before running.

Hamlib includes a built-in Dummy radio (model number 1) that answers every command with made-up but plausible values. It exists so developers can test without hardware. If it is selected — for example by following an online example that uses rigctl -m 1 — everything looks perfect and nothing is ever sent to your real radio. RigCheck will not run its tests against the Dummy radio; make sure the model shown at the top of the results is your actual rig.

Only one program can hold a serial port at a time. If WSJT-X, Fldigi, JS8Call, Winlink, or a rig-control server such as rigctld or Flrig is running, it owns the port and RigCheck cannot open it. Close the other program, or disconnect rig control inside it, then try again. That is usually not a fault — it means your rig control already works through that program.

RigCheck itself never opens a network port, so Windows Firewall will not ask about RigCheck. If RigCheck suggested starting rigctld (Hamlib's rig-control server) and Windows then asks about rigctld.exe, that is expected: rigctld listens for connections. Tick Private networks and click Allow access. You do not need to allow it on public networks. If you clicked Cancel in the past, Windows created a Block rule and rigctld will silently fail until that rule is removed in Windows Firewall settings.

Nothing unless you say yes. On first launch RigCheck asks whether it may send anonymous diagnostic reports, and you can change the answer in Settings at any time. If enabled, it sends the RigCheck and Windows versions, whether Hamlib was found, and after each test run the radio model, serial settings, USB cable identifiers, and which tests passed or failed. That is exactly the data that improves the radio and cable database for everyone.

Never sent: your callsign, computer name, file paths, serial numbers, or IP address. The only identifier is a random ID created on first run, shown as a Support ID in Help › About. Every report is also kept on your PC and can be read under Help › View collected data. See the Privacy page.

Yes, and you do not need to be a programmer. RigCheck keeps all of its text in one file, Strings.resx. To translate, copy that file, name it for your language (for example Strings.de.resx), translate the text between the <value> tags, and open a pull request — or attach the file to a GitHub issue if you prefer. Machine translation is a fine starting point; a native-speaking ham correcting the radio terms is what makes it good.

Translators are credited by name and callsign in Help › About and in the repository. Product names like ShackDesk, RigCheck, and Hamlib stay in English, and ham terms like CAT, PTT, and VFO are usually left as your local club says them. The full guide and glossary are in TRANSLATING.md.

MarkMySpot

MarkMySpot is a free web app that reads your GPS location and displays it in formats amateur radio operators use — Maidenhead grid square, decimal degrees, and DMS. One tap copies all three formats to your clipboard. It runs in any browser on Android or iPhone, works offline after the first load, and can be installed to your home screen as a PWA.

Learn more about MarkMySpot  ·  MarkMySpot FAQ & help

MarkMySpot needs your GPS coordinates to calculate your grid square and display your location. Your location is used only on your device — it is never sent to any server, never stored, and never shared. All calculations happen locally in your browser. There is no backend.

When the app first opens, tap Allow when your browser asks for location permission. If you need to re-enable permission later, see the location troubleshooting guide.

iPhone: You must use Safari — Chrome and other iOS browsers cannot install apps to the home screen. In Safari, tap the Share button (rectangle with arrow) → Add to Home Screen. Also make sure Safari has iOS location permission: Settings → Privacy & Security → Location Services → Safari → While Using the App.

Android: Open MarkMySpot in Chrome, tap the three-dot menu (⋮) → Add to Home screen or Install app.

See the full installation guide for step-by-step instructions including Samsung Internet.
